# Jane Street exchange architecture — specification-by-specification comparison

- **Status:** Source-backed **Current** comparison at [`main@8e3ac2f`](https://github.com/andrewkoumoudjian/bunting/commit/8e3ac2f8901f5dab3bec57a934f1bda6b6ddd6c7), plus **Target** requirements. This document changes no implementation.
- **Source:** User-provided automated transcript (153 numbered lines) of a Jane Street talk about exchange design, supplied 2026-10-12. References `T:Lx–y` refer to lines in that supplied transcript, **not** a recording independently verified by Bunting. Speaker-specific numbers and anecdotes are not Bunting SLAs or proof of current Jane Street internals.
- **Decision record:** [ADR 0053](../adr/0053-replayable-exchange-publication-and-runtime.md).
- **Product:** Bunting is a deterministic Rust market/exchange simulator for RIT-class cases and QUARCC competitions, not a regulated real-money exchange.

Status vocabulary: **Aligned** = core invariant is implemented, not performance-proven; **Partial** = existing behavior with specified gap; **Gap** = not found in audited implementation; **Different** = intentional difference, not automatically a defect. **P0** means losslessness/correctness, **P1** means reliability/performance improvement, **P2** means optional architecture under a measured requirement.

## 1. Order matching and market semantics

| ID | What the talk describes | Bunting currently | What an exchange-quality Bunting should guarantee | Status / gate |
|---|---|---|---|---|
| M01 Price-time CLOB | Descending bids, ascending asks, then time priority (T:L1–7). | Price-ordered `BTreeMap` levels with FIFO priority per level in [book.rs](../../packages/bunting-engine/src/book.rs); one book per `ListingKey`. | Deterministic price/time priority, checked fixed-point quantities, reproducible state and events. | **Aligned**; randomized ordering and snapshot tests. |
| M02 Add, cancel, cancel/replace, executions | Principal order message classes (T:L7–11). | [`CommandPayload`](../../packages/market-events/src/lib.rs) has submit/cancel, with executions emitted; no canonical atomic replace in the core. | Keep submit/cancel atomic. Specify priority-loss, idempotency and race semantics before adding replace. | **Partial**; replacement is an optional product feature, not mandatory from the talk. |
| M03 Crossing and aggressive orders | A marketable order immediately trades (T:L7–9). | `Book::execute` sweeps eligible resting liquidity at resting prices and emits fills. | Best-price/earliest-time fills, maker-price execution, no fill beyond aggressor limit, both sides settled atomically. | **Aligned**; crossing, partial, market sweep and ledger reconciliation tests. |
| M04 Price improvement and order incentives | The aggressor usually receives price improvement; hidden-order rules can reward price probing (T:L27–31). | Maker-price execution, iceberg, post-only; incentive safety depends on policy. | Define price improvement, hidden display, self-trade policy and abuse incentives for each added order type. | **Partial**; adversarial probing/cancel-storm tests before new order policies. |
| M05 Multiple instruments and shared risk | Some operations reach multiple instruments atomically, so symbol sharding is not automatically correct (T:L13–15, L99–111). | One `RunState` owns listing books, participant risk and one economic ledger. | Atomic cross-venue reservations, account limits and shared risk; no independent order writers without an atomicity protocol. | **Aligned for shared authority**; multi-leg atomic execution is not an implemented feature. |
| M06 Timed cancellation (“cancel fairy”) | A separate observer schedules a future cancel rather than the CLOB running arbitrary timers (T:L43–47). | `RunState::next_due` plus a journaled venue `ClockTick`; GTD/DAY expiry and calendar in [ADR 0037](../adr/0037-run-clock-calendar-and-auctions.md). | All timed economic changes must be ordinary replayable inputs. No wall-clock side effect inside matching. | **Aligned**; crash/expiry boundary replay. |
| M07 Auctions | Separate calculation maximizes crossed volume; final result reenters matching (T:L47–49). | `Book::auction_price` sums book levels separately for each candidate price, O(P²) over P price levels, in the writer. | First replace with deterministic O(P) cumulative demand/supply sweep; offload only when measured and version-validated, with atomic final uncross. | **Partial, P1**; exhaustive small-book oracle for price, volume, tie-breaks and matches. |
| M08 Fast cancel locators | Port can translate client order identity to prevalidated matcher locator (T:L63–65). | Canonical 128-bit `OrderId` indexes `BTreeMap<OrderId, BookOrder>`; no order-slot locator. | Keep canonical identity; generation-checked preallocated slots are optional if profiling proves benefit. Never trust raw external pointers. | **Different, P2 optional**; stale-slot and cache-miss benchmarks. |

## 2. Sequencing, deterministic state machines and atomicity

| ID | Talk | Bunting currently | Requirement / design judgement | Status / gate |
|---|---|---|---|---|
| S01 One primary matcher | In-memory matching application orders all accepted transactions (T:L33–39). | [admission sequencer](../../apps/bunting-server/src/admission.rs) is the sole committing thread, using [`bunting-engine`](../../packages/bunting-engine/src/lib.rs). | One logical writer per run; FIX, BNP, agents, timer and operator work all pass through it. | **Aligned**; mixed-client deterministic replay. |
| S02 Total transaction order | Downstream applications reproduce state by applying the primary's ordered message stream (T:L67–79). | [origin store](../../packages/origin-store/src/lib.rs) journals commands, result, canonical events, admission and chain hash. | A committed journal prefix must yield the same authorized output for every consumer under a versioned deterministic projection. | **Partial, P0**; journal-to-output replay tests. |
| S03 Per-topic optimistic “locks” | Contributors propose per-topic sequence numbers, retry conflicts after observing winning transaction (T:L113–135). | Run-wide expected sequence is assigned at release; command IDs are idempotent, no optimistic per-topic protocol. | **Do not** adopt topic conflict protocol without a multi-writer need; run-wide deterministic sequencing is simpler for Bunting. | **Different by design**; cancel/fill conflict tests. |
| S04 Executions from an input | One aggressing order deterministically causes both counterparties' executions; passive replica regenerates them (T:L123–143). | `RunState::submit` produces fill events in one command transaction; publisher distributes afterward. | Maker/taker and ledger effects are indivisible as an economic decision; distribution holes must be detectable and recoverable. | **Aligned core / Partial distribution, P0**. |
| S05 Stateful rejects are sequenced | Even a cancel reject may need a globally sequenced cause if the protocol uses it to evolve durable state (T:L127–137). | Engine rejects are eventful; FIX has separate session WAL; some pre-admission rejects are protocol-local. | Explicitly classify canonical economic rejects, durable session rejects and ephemeral transport errors; none may change persistent client state without recovery provenance. | **Partial, P0 audit**; crash around every class. |
| S06 No local timer mutation | All state changes need deterministic represented inputs (T:L145–149). | One run clock and journaled ticks; deterministic jitter recorded by the admission path. | Keep clock, randomness and host I/O outside engine transitions; use journaled input for schedules. | **Aligned**; offline replay without sockets. |
| S07 Explain any execution | Total order identifies the information available when trade occurred (T:L145–149). | Journal, hashes, checkpoints, replay and ledger exist. | Reproduce precise maker/price/priority, quantity, fees, reservations and relevant rule version for any trade or reject. | **Aligned economically / projection work P0**. |

## 5. Source-backed findings and implementation gates

1. **P0 — no silent missing feeds.** [`PublishingOrigin::execute_admitted`](../../apps/bunting-server/src/distributor.rs) currently uses `public_updates(...).unwrap_or_default()` and defaults private projection failures; a durable economic commit can therefore proceed without a required derivative update. This is a **source-backed failure path**, not evidence of an observed production incident. Remove the fallback and implement explicit unavailable/rebuild/replay semantics.
2. **P0 — every persistent projection recoverable.** The L2 path rereads full visible depth for touched listings; L3 rebuilds displayed orders and compares to mutable process-local projection caches, O(live orders) for touched listings. Reconstruct exactly from canonical mutation deltas or deterministic journal replay, including anonymity, maker references, partial fills and iceberg refresh.
3. **P1 — deep BNP replay.** The [distributor](../../apps/bunting-server/src/distributor.rs) retains 16,384 batches; [BNP host](../../apps/bunting-server/src/bnp_host.rs) reports `ResumeStatus::Gap` if not covered, unlike FIX's journal catch-up. Recover from the durable origin where available, or specify an authenticated snapshot/reset.
4. **P1 — O(P) auctions.** The price selection currently recomputes aggregate supply/demand for each price, O(P²) in number of price levels. Implement a deterministic ordered sweep and compare against a slow oracle, tie-breaks and fill-by-fill.
5. **P1 — quantify performance before structural changes.** Measure release build on recorded CPU/storage with client count, symbols, order/cancel mix, book depth, p50/p99/p99.9, sustained throughput, memory, allocation and stage time for matching, journal, projection and socket.
6. **P2 — availability and book internals only after evidence.** A passive follower, binary journal, preallocated order arenas, multicast, or multiple matching partitions are candidate optimizations, **not required adoption of the talk**.

**Cross-cutting acceptance:** fault-inject pre/post durable write, post-commit projection, fanout and socket write; verify the maker and taker see identical irrevocable economic fills after reconnect. Rebuild every stream from genesis/checkpoint+journal and prove sequence continuity and consistent hashes. Test equal-path delivery bias while retaining true/virtual distance; cross-venue shared limits must remain atomic. Preserve archived-run reproducibility and host-neutral pure Rust transitions.
